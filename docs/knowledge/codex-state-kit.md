# codex-state-kit：用户提供的 Gemini 总结（未核验）

来源：群管理员在 2026-09-20 提供的 Gemini 总结；未提供仓库 URL、commit 或可追溯的 [cite: 2] 引用。
本文可用来解释“这份总结声称项目做什么”，不能作为 OpenAI 内部调度机制、代码实际实现或效果的证明。

该总结把 codex-state-kit 描述为本地状态管理与代理转发工具：keeper.py 检查本地 state 的过期时间，
通过 Clash Controller 临时切换网络后发起探测请求，尝试提取 current_turn_state，保存后切回原网络；
inject_proxy / gpt-load 在后续请求中读取并注入该状态。总结提出“采集状态和使用状态分离”的设计，
目标是缓解排队、Overload、429 和用户感知的回复质量下降。以上均是总结中的描述，尚未读过实际仓库代码。

未核实且现已过时的说法：HTTP 292 代表高质量/完整算力；HTTP 312 / 200 意味着降级；
current_turn_state 打票后注入能保证完整模型和算力。2026-09 之后社区与 State Kit 官方说明都已不再使用 292/312 打票。
讨论旧总结时要明确「打票已经失效」，不得再按票据长度承诺效果。当前以降智识别为准：上游 `openai-model` 与请求模型不一致记为已降级。

已核对的公开资料：OpenAI API 错误文档 https://developers.openai.com/api/docs/guides/error-codes
说明 429 有请求速率超限、请求速率骤增、余额或组织支出限额等不同原因；需结合响应 error code、
Retry-After 和账户限额排查。该公开错误文档没有证实上述 292/200 与“满血/降级”的对应关系。
当成员询问 429、排队或回复异常时，先确认使用的产品/接口、实际错误码、时间、所选模型、上下文长度、
代理/中转链路及重试方式，再提出可以验证的排查步骤；不要把所有故障归因于“降智”。
